# 樂活狂飆 LOHAS RUSH

## 正式遊戲定位與開發基準

> 開車探索城市，從環境與任務認識樂活服務。

- **遊戲類型**：3D 開放式城市駕駛探索遊戲。
- **核心玩法**：自由駕駛 × 城市探索 × 據點任務。
- **遊戲目標**：讓玩家在駕駛與探索過程中，自然認識樂活集團的服務據點與長照生態系。
- **開發原則**：先完成 V0.1 穩定性驗收，再逐步規劃與實作 V0.2 的探索功能。現有功能與歷史 V1 標記不代表穩定性驗收已完成，驗收結果以實際測試紀錄為準。

本定位是後續規劃基準。據點任務與接送體驗是城市探索的一部分，不將遊戲改為純接送模擬器；也不與獨立專案《長照人生旅程 3.0》的回合制教育玩法混合。保留既有功能，在 V0.1 驗收完成前不提前新增 V0.2 探索功能。

### 遊戲設計的四項核心原則

1. **自由駕駛優先**：玩家可以自由探索，不必強制依照任務路線行駛。金色導航路線是引導；主線據點的完成順序不限制玩家自由行駛或提前探索其他區域。
2. **五站日照主線**：大和 → 安南 → 龍山 → 義合 → 新營，透過不同任務認識各據點。現階段保留五站依序抵達的規則；各站差異化任務屬後續設計，不視為已實作。
3. **樂活服務支線**：診所、團膳工廠、居服站、護理之家等，透過城市探索逐步發現。現有建築或資料不等同支線任務已完成，支線互動於 V0.1 驗收後逐步規劃與實作。
4. **探索與互動並重**：不以競速為唯一目標，透過地標發現、任務完成及探索紀錄提供回饋。探索紀錄及新增回饋機制須另行實作與驗收，不在本次定位確認中提前開發。

首頁維持既有 React、TypeScript、React Three Fiber、Three.js 與 Zustand 遊戲。公務車五站任務、駕駛操作、HUD、第三人稱鏡頭、爺爺奶奶上下車及照服員陪同推輪椅均維持原有流程。現行任務是五站，不因新的生態城市規劃而更動。

長照生態城市目前以**未啟用的規劃資料與可重用低面數建築元件**分階段建置，位於 `src/data/planning/` 與 `src/game/buildings/PlannedBuildingProxy.tsx`。目前不將新城市、建築互動或相機特寫接入現行遊戲；既有遊戲的 HUD 與操作引導依 V0.1 驗收需求完善。地址、實際建物、合作關係細節及服務範圍仍須正式資料確認。

### 玩法與狀態

- 自由接近據點會記錄首次發現，通知不暫停駕駛。再次靠近或重新載入不重複播放同一據點的首次通知。
- 點右上「探索日記」查看 12 個據點的總數、已發現數與已完成數；可依「全部／五間日照／其他服務」及「未發現／已發現（未完成）／已完成」篩選。
- 首次查看據點卡必須完全停穩，且位於 8 個遊戲單位的互動範圍。讀取的是物理位置與速度，不以 HUD 四捨五入的車速取代停車判定；接送動作進行中也不能開始新互動。
- 看完據點卡後按「確認並記錄探索完成」才會收錄；直接關閉不算完成。已收錄的日記可在面板內隨時重讀，這是閱讀個人筆記，不會再次觸發世界據點互動。
- 開啟日記時暫停駕駛／接送並阻擋遊戲快捷鍵，關閉後恢復。從工具列開始駕駛會離開按鈕焦點，避免 Space 變成開面板而未煞車。
- 五站主線仍為大和 → 安南 → 龍山 → 義合 → 新營。主線抵達與探索完成分開；主線自動抵達只會增加可能的發現，不替玩家確認日記。R／「重新開始旅程」保留探索資料。
- GPS 新增 `?` 未發現、`◇` 已發現、`✓` 已完成探索標記；原金色導航、五站數字與抵達標記保留。未發現的日記項目與探索標記不顯示完整故事；原五站導航名稱仍照常顯示。

### 據點資料與本機存檔

`src/data/explorationLocations.ts` 沿用現有五間日照與六個服務點的 ID／抵達位置，另以既有總部 ID 增加同棟總部與 1F 現煮食，共 12 個探索據點。五間日照發現半徑 28、服務點 20、總部 32，均為遊戲單位。每筆包含 `id/name/category/description/position/discoveryRadius/interactionRadius/journalTitle/journalContent`；日記內容均標示暫定／情境示意，未臆造真實機構介紹、地址、電話或服務承諾。

存檔只寫入 localStorage 的 `lohas-rush:exploration`：

```json
{"version":1,"entries":{"daihe":{"discoveredAt":1793952000000,"completedAt":null}}}
```

只保存個人的據點 ID 與發現／完成時間，不儲存整個 Zustand、車位、速度、主線進度、通知或故事文案。載入時驗證版本、資料結構、時間與目前的據點 ID；損壞內容安全恢復，部分無效項目會移除並提示。預留 v0 的 `discovered/completed` ID 陣列格式轉換，驗證後寫回 v1；不認識的版本保留原始存檔，本次改用記憶體，直到玩家明確清除。

本機儲存受限／寫入失敗時仍能遊玩，面板會提示資料可能無法在重載後保留。「清除探索資料…」必須再按「確定清除探索資料」，只刪除探索存檔，不影響主線與其他設定。清空時仍在附近的據點，需離開發現範圍再靠近才會重新發現。

世界資料與個人資料分離於 `src/data/explorationLocations.ts`、`src/exploration/` 及 `src/stores/exploration.ts`。個人 store 可獨立建立並注入儲存介面、存檔 key、時鐘與玩家位置讀取器，預留未來每位玩家的資料隔離；本階段仍只有本機單人日記，沒有帳號或跨裝置／跨分頁合併同步。

## V0.1 穩定性修復與操作引導（2026-11-05，歷史驗收）

修復重置後立即按油門可能被忽略的競態：鍵盤與觸控輸入在重置動作當下同步清除，物理更新與延遲 effect 不再刪除重置後的新輸入。固定步長、碰撞、城市配置與五站順序維持原有規則。

## 快速開始

### 獨立入口：樂活長照城市

`public/care-city/index.html` 是獨立的 Low-Poly 3D 互動服務城市，不取代首頁駕駛遊戲。啟動開發伺服器後，開啟 `/care-city/index.html`；GitHub Pages 建置後的入口為 `/lohas-rush/care-city/index.html`。這次僅產出本機檔案，未執行部署。

單一 HTML 內含完整 CSS、36 筆單位 JSON、Three.js 0.175.0、OrbitControls、GSAP 3.13.0、FontAwesome Free 6.7.2 的 SVG 圖示與場景程式碼，直接開啟檔案也能運作。Google Noto Sans TC 為選用網路字型，無網路時使用系統中文字型。引擎與圖示不依賴 CDN，授權聲明保留於內嵌程式碼。

可使用分類、搜尋或建築點擊來聚焦；總部與 1F 現煮食為同棟垂直分層，資訊抽屜提供樓層切換。城市包含 5 間日照、12 間住宿機構、居家與 8 個醫院看護網絡節點，以及壹吉棒、大心復康巴士。巴士與現煮食車輛沿示意道路巡行，可暫停；支援鍵盤清單、減少動態偏好與 WebGL 不可用時的資訊備援。

據點位置、道路及車隊路線為示意；醫院網絡依提供名單呈現，特約現況仍須確認。未提供的地址、電話與服務區域均標示待確認，不建立虛構聯絡方式。此獨立示意頁不改變遊戲的世界座標、碰撞與五站任務。

驗證：`npm run build`，以及在開發伺服器啟動後執行 `node tests/care-city.browser.mjs`（預設埠 5191，可用 `TEST_CARE_CITY_URL` 指定完整網址）。Chrome 測試涵蓋分類數量、搜尋、總部分層、Raycaster 點擊、旋轉拖曳、車隊暫停、390px 手機版、離線直接開啟 HTML、減少動態與 WebGL 備援。

需要 Node.js 24 以上，以及支援 WebGL 2 的瀏覽器。

```sh
npm ci
npm run dev
```

| 輪椅跟隨（自動，側移 2.5 m） | 5.5 m | 3.7 m | 52° | 40（輪椅探索期間） |

按 C 或點按車速面板「鏡頭」切換，以 0.65 秒 ease-in-out 過渡距離、高度、前視與 FOV，並套用追蹤阻尼。前視會加入有上限的速度預測，鏡頭保持世界向上、不跟車身翻滾。R／重新開始會恢復跟車視角，直接切回出生點而非從遠處慢慢追上。

cameraCollision.ts 以帶 0.4 m 裕度的線段／三維包圍盒計算建築、山丘與噴水池底座的遮擋：碰到遮擋立即縮短車輛到鏡頭的距離，離開後以阻尼恢復。這是保守幾何近似，沒有逐面碰撞、環繞鏡頭、Timeline、震動或完整 Cinemachine 功能；樹木、燈桿及部分裝飾未納入鏡頭遮擋。

更新順序明確設為車輛物理／插值 -2、鏡頭 -1，再由一般場景回呼更新標記與繪製，避免讀取前一幀車位；負優先序不接管渲染迴圈，依 [React Three Fiber useFrame 文件](https://r3f.docs.pmnd.rs/api/hooks#negative-indices) 使用。高頻鏡頭狀態留在 controller／refs，Zustand 僅保存低頻模式選擇；元件卸載由 useFrame 清除註冊。

2. 安南日照中心
3. 龍山日照中心

## 程式化基地生成

已將提供的 Unity CityGenerator 邏輯轉為 TypeScript。buildingLots.ts 整合外環沿線及七片街區，預留最大 12×12 公尺建築，排除道路、河流、河岸及固定服務設施；目前有 107 個可用基地（11 個外環基地及 96 個街廓基地），生成五中心與 102 間虛構店家。五中心名稱、任務順序、照片待補狀態與重置功能仍保留。

### 稀疏與均勻配置規則

CITY_GENERATION_RULES 預設 minShopGap = 8、minCenterDistance = 220，指定五個獨立中心區域。生成器以固定種子打亂候選基地順序，再做有上限的回溯搜尋；不以隨機機率決定是否漏掉某間中心，不修改傳入的中心清單，也不在配置失敗時默默放寬間距。

- 五間中心分別配置於西北、西南、南城、東南、東北街區，每區恰好一間，每區都有 16 個等容量候選基地。
- 檢查所有中心配對的建築座標及道路抵達座標，兩者均不得少於 220 公尺；不只檢查上一間，也不以基地陣列距離冒充實際空間距離。
- 沿 spawnPoints 的生成順序，第一間中心前及每兩間中心之間至少放 8 間真實生成的店家，不以空基地湊數。這是生成序列的間隔，並非保證玩家沿任意導航路線恰好經過 8 間；空間稀疏由物理距離與五區分布另外保證。
- 若基地不足、區域不存在、店家清單為空但仍要求店家間隔，或搜尋未能在上限內找到符合距離／間隔條件的完整配置，會明確報錯；不會只生成部分中心或讓相鄰中心通過。最多搜尋 100000 個候選步驟，避免不合理設定長時間卡住。

## 外圍街道與街廓

streetGrid.ts 保留西側、南側街坊，另外加入西北、西南、南城、東南、東北五片大型街區，以長條聯絡道路接回原路網，東側地區由橋梁連通。完整城市目前有 376 個道路節點、483 條道路邊，可玩邊界為正負 448 公尺，即約 896×896 公尺；較先前 320×320 公尺的範圍增加約 7.84 倍面積。

街道寬 12 公尺，兩側各留 2 公尺人行空間。32×32 公尺街廓共 96 格，每格一個 16×16 公尺方形基地，避免基地與人行空間重疊；最大建築仍為 12×12 公尺。每個基地有獨立道路入口節點。新增 z = 260 的南橋，與 z = 0 的原橋共用河岸／橋欄碰撞資料，導航不會穿越未架橋的河面。

Three.js 使用共用路塊幾何：直路、轉角、丁字與十字路口。資料辨識出 57 個十字、87 個丁字、22 個轉角，交會處以獨立平面蓋住路塊接縫；不需新增 Unity／ProBuilder 或 Blender 資產。街道、基地與建築沿用批次繪製，地圖同步顯示五片外圍區域，中心編號與車輛圖示保持可讀尺寸。尋路改用預建鄰接表及最小堆積 Dijkstra，避免地圖放大後反覆掃描所有道路。全路網均檢查車體淨空及五中心可達性。

## 架構與效能

- roadNetwork.ts：道路節點、邊、出生點、城市邊界與尋路。
- streetGrid.ts：七區街道、五個中心專用區域、區間聯絡路與南橋、32 公尺街廓及獨立入口節點。
- cityGenerator.ts／buildingLots.ts：固定種子的無重複基地分配、可用基地與虛構店家樣式。
- locations.ts：五中心名稱、位置、抵達區與照片需求。
- services.ts／landscape.ts：獨立服務資料、山丘、河流、河岸與橋欄。
- city.ts：組合建築及碰撞來源；場景建築尺寸與碰撞共用資料。
- StaticScenery.tsx：道路、建築與樹木的共用幾何及實例化批次；環道獨立環面避免接縫重疊。
- Car.tsx／vehicle：120 Hz 有界固定步長、最多 12 子步進、單幀 delta 上限 0.1 秒，以及車輛／鏡頭畫面插值。
- game/camera/：虛擬鏡頭設定、Brain、三維遮擋縮距與實際攝影機更新，獨立於車輛物理。
- stores/game.ts：低頻任務、重置、HUD 與地圖座標，每秒約 10 次顯示更新；未每幀寫入 Zustand。
- NavigationRoute.tsx／RouteMap.tsx：依相同路網繪製場景導航與桌機地圖。

手機採 DPR 1 並停用多重採樣／即時陰影，車底使用簡單接地陰影；桌機保留 1024px 陰影。沒有新增大型依賴、後端、多人、交通 AI、真實台南地圖、棋盤或複雜剛體物理。

車體以半徑 2.45 公尺的保守包圍圓處理建築、噴水池、停放餐車、山丘、河流、河岸、橋欄與城市邊界。橋梁為平面可駕駛示意，河面僅在橋下留通道，橋欄阻止側向離橋；前進最高 120 km/h（約 33.33 m/s），倒車最高 8 m/s。持續按 W／↑ 或手機油門可漸進加速超過 80 km/h，放開油門滑行減速，Space／手機煞車可煞停。樹木與街燈仍是裝飾，靠轉角可能提早碰撞。鏡頭已具備上述包圍盒縮距避讓，極近障礙時視野仍可能較窄。

### 街景實例池與循環回收（2026-11-03）

在既有預載入與四個區塊容器之上加入 `src/game/assets/StreetModelPool.ts`，由 TrackManager 實際使用。GameAssets 的同次預載重用同一 Promise，四個街景模板各載入一次；跨區不發出模型請求。依模型種類與尺寸分池，先預熱所需實例，離區模型移除父節點後回池，進區只更新位置、朝向、名稱及店家資料；預熱後不隨行駛反覆 clone。左右街側建築仍按既有基地位置及面向道路的旋轉配置。

每個種類／尺寸的容量上限，取全城單格數量最高的四格加總，因此任意 2×2 可見區塊都有足夠實例。先回收所有離開區塊，再填入新區塊，不因處理順序多造一批模型。倒車、轉彎、跨多區與重置共用同一池；fallback 換成成功載入的模板時，淘汰舊版實例並一次預熱新版，之後繼續重用。不會在回池時 dispose 共用材質／幾何，卸載才清理快取。

這裡循環的是既有城市的詳細街景實例；城市仍是有邊界的五中心自由駕駛地圖，沒有改成沿 +Z 的無限跑道。道路、基本建築、任務與碰撞常駐，五中心位置不會隨回收改變。沒有提供 `tainan_building.glb` 或可用老屋模型，仍保留原有一般店家的幾何外觀；未新增或假設第三方素材。

`npm.cmd test` 33 項通過，新增 5000 次含負座標、倒退／跳區的反覆切換：預熱後模型物件身分持續重用、建立數不增加、每庫仍只有四次模板載入，常駐實例數固定在容量上限內；也檢查 fallback 模板換代、缺店屋模型及卸載清理。`npm.cmd run build` 通過，主 chunk 約 1.25 MB，仍有大小提示。這些是實例數量與資源生命週期檢查，不是瀏覽器記憶體或 FPS 的保證。

Chrome 的 GLTF 與物件池檢查通過：以實際載入器取得二進位測試模型，在瀏覽器內重複切換 1000 次街景區塊，實例建立數不增加、常駐數維持容量上限；實際鍵盤跨區、超過 80 km/h、煞車與重置、桌機／手機／鏡頭及正常 GLB 公務車檢查也通過。完整腳本最後在車輛 fallback 的鍵盤轉向等待逾時，加入 bringToFront／點擊畫布／確認頁面焦點後，`npm.cmd run test:vehicle` 的正常與 fallback 兩種狀態均獨立重測通過；焦點修正後未再次執行完整 test:browser，因此本次不列完整腳本通過。測試使用既有 5175 Vite server。1000 次區塊切換是程式化管理器壓力測試，不代表 1000 次完整實際試駕；未測真實老屋模型、實體裝置效能與長時間 GPU 記憶體，也未重跑五中心完整路線。

## 未完成與效能限制

- 五中心及其他服務建築的實景照片建模尚未完成；待授權照片與必要尺寸。

- 大型城市仍保留有限視距與中央區域的即時陰影範圍，遠區陰影細節尚未全面調整；生成店家與街道繼續使用批次繪製，未新增外部套件。
- 場景為有限範圍低多邊形原型，沒有真實地形高程或橋面坡度；樹木與燈桿非碰撞物件。
- 未提交、推送或發布本次變更；先前鍵盤、觸控、資訊欄與效能優化的未提交修改仍保留。
